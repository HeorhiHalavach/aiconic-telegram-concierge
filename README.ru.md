# AICONIC · дирижёр в Telegram + окно администратора

Клиент пишет на аккаунт салона в Telegram — модель отвечает от лица этого
аккаунта, сама записывает на свободное время и напоминает о визите. Не справилась
(здоровье, торг, отмена) — передаёт разговор человеку и в этом чате замолкает.

Администратор работает на **своей странице**: одна лента всех мессенджеров,
🔴 помечено там, где ждут именно его, карточка клиента рядом, ответ уходит клиенту
прямо оттуда. Открывается с телефона.

| Собрано | Что делает |
|---|---|
| **Этап 1** | дирижёр отвечает, записывает, напоминает — [план](docs/STAGE-1-TELEGRAM.md) |
| **Этап 2** | окно администратора: лента, карточка, метки — [план](docs/STAGE-2-INBOX.md) |

Что проверяется этим всем: **не выдумывает ли модель цены и время**, держит ли тон,
признаёт ли незнание, уходит ли вопрос о здоровье человеку. Ни одной выдуманной цены
и ни одного выдуманного свободного окна за все прогоны.

🇬🇧 Англоязычный разбор проекта для портфолио: в этом репозитории `README.en.md`, в
публичном снимке (`tools/публичный_снимок.py`) — `README.md`, а этот файл — `README.ru.md`.

🖼 Посмотреть окно администратора без Telegram и ключей:
`.venv\Scripts\python.exe tools/демо_окна.py` → `http://127.0.0.1:8742`.

## Что нужно перед запуском

1. **Два аккаунта Telegram.** Один играет салон (на нём наша сессия), со второго
   вы пишете как клиент.
2. **Зарегистрировать аккаунт салона в официальном приложении**, заполнить имя и
   фото, **дать ему отлежаться несколько дней** и написать `@SpamBot`, чтобы
   убедиться, что ограничений нет. Свежий аккаунт плюс вход по API в тот же день —
   худшая комбинация из возможных.
3. `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org) →
   *API development tools*. **Один `api_id` на один номер.**
4. Ключ Cerebras на [cloud.cerebras.ai](https://cloud.cerebras.ai).
   ⚠️ **Карту привязать обязательно** — без неё API не активен и любой запрос
   возвращает `402 payment_required`. Привязка даёт $5 кредитов на 30 дней;
   списаний без вашего согласия не будет. Лимиты пробного тарифа: 5 запросов/мин,
   1 млн токенов в сутки **и в час** — это 4 полных прогона имитации в сутки.

## Установка

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`, затем получите строку сессии:

```bash
.venv\Scripts\python.exe login.py
```

Скрипт предложит два пути. **По умолчанию QR** — в консоли рисуется квадрат, на
телефоне в аккаунте салона: *Настройки → Устройства → Подключить устройство*.

⚠️ **Вход по коду для нас ненадёжен по устройству платформы.** Telegram не отдаёт
SMS сторонним клиентам («only the official applications can receive a login/signup
code via SMS/call»), а код «в приложение» уходит только в уже живые сессии и может
не дойти. QR Telegram сам называет доступным сторонним клиентам — он этой
зависимости не имеет. Подробно: [docs/STATUS.md](docs/STATUS.md), раздел
«Доставка кода входа».

Скрипт напечатает строку сессии и ваш `user_id`. Строку положите в `.env` как
`TG_SESSION`.

> ⚠️ Строка сессии — **полноценный доступ к аккаунту**. `.env` в git не попадает.

## Запуск

```bash
.venv\Scripts\python.exe main.py
```

**Первый запуск оставьте `TG_WHITELIST` пустым** — это режим наблюдения: процесс
логирует id всех, кто написал, и **никому не отвечает**. Возьмите нужный id из
`logs/dialogs.jsonl`, впишите в `TG_WHITELIST` и перезапустите.

Чтобы мгновенно замолчать — создайте рядом с `main.py` файл `STOP`.

## Тесты

```bash
.venv\Scripts\python.exe -m pytest             # логика и заслоны
.venv\Scripts\python.exe tools/mutants.py      # у заслонов есть зубы
.venv\Scripts\python.exe tools/simulate.py     # живая модель, многоходовые диалоги
```

Третий — **имитация клиента**: настоящая модель, настоящий дирижёр, настоящие
заслоны и настоящий файл записей; подменён только Telegram. История чата
накапливается, как в мессенджере. Нужна потому, что все самые дорогие дефекты
этапа нашлись только в многоходовом диалоге с живой моделью, а тест с
подменённой моделью наследует представление автора о том, что модель ответит.

Второй скрипт по очереди ломает каждый заслон и проверяет, что защищающий его
тест краснеет. Зелёный тест не стоит ничего, пока не доказано, что он умеет
отвергать. **Добавили заслон — добавьте мутацию в `tools/mutants.py`**, иначе он
не считается проверенным.

## Окно администратора

```bash
INBOX=on
INBOX_TOKEN=<латиница и цифры>
INBOX_PORT=8000
```

Запустить `main.py` и открыть с телефона `http://<IP-этой-машины>:8000`. Токен
страница спросит один раз и запомнит.

- **Мессенджеры** — первый экран: где сколько ждут помощи;
- **Лента канала** — свежие сверху, ждущие человека над всеми;
- **Разговор** — переписка живьём из Telegram, карточка клиента, поле ответа.

Ответ администратора идёт через тот же `Sender`, что и ответ модели, но заслонов у
него меньше — и это названо прямо в [ARCHITECTURE](docs/ARCHITECTURE.md): белый список
остаётся, а `STOP`, лимит и проверки «не выдумала ли модель» не применяются, потому что
текст написал человек.

⚠️ **В карточке клиента нет данных о здоровье** — только отметка «вопрос о здоровье».
Переписка показывается живьём из мессенджера и в наше хранилище не копируется.

⚠️ **Только локальная сеть.** HTTPS нет, токен идёт открытым текстом — в интернет так
выставлять нельзя.

## Данные

```
data/price.yaml      ваш   · услуги, цены, правила — код только читает
data/schedule.yaml   ваш   · мастера, часы, график — код только читает
data/bookings.yaml   кода  · записи, код перезаписывает целиком
```

Код **никогда** не трогает первые два файла, поэтому ваши комментарии в них
сохраняются. Свободные окна не хранятся, а вычисляются: хранимый список сразу
разошёлся бы с записями.

Всё время в этих файлах — **местное время салона** (Тбилиси, UTC+4). Даты
сообщений Telegram приходят в UTC; смешивать их нельзя.

## Как устроено

```
Telegram → приём (фильтры, группировка) → контекст из Telegram + прайс
        → заслон на медицину → модель → Sender → ответ клиенту
                                          │
                                          └→ не справилась → метка «нужен ответ»
                                                                │
                              браузер ← страница ← inbox/api.py ←┘
                                 └─ ответ администратора → Sender → клиенту
```

## Напоминания

Записали клиента — за день и за 2 часа до визита ему уходит напоминание. Это
**единственное**, что система отправляет первой, поэтому обставлено отдельно:

- идёт через `Sender` → слушается файла `STOP`, белого списка и лимита;
- текст фиксированный, **модель к нему не подпускается**: проверить сообщение,
  уходящее первым, перед отправкой некому;
- отметка об отправке лежит в `bookings.yaml`, а не в памяти процесса — перезапуск
  не отправит заново;
- процесс лежал сутки → напоминания о прошедших визитах гасятся молча, а из двух
  созревших уходит только ближайшее к визиту;
- работают, **пока запущен `main.py`**.

Выключить: `REMINDERS=off` в `.env`. Тогда бот про напоминания и не обещает —
обещание, которого система не выполнит, здесь считается ошибкой.

## Как устроено — правила безопасности

Два правила, на которых держится безопасность:

- **Модель не умеет отправлять и не умеет писать.** Она возвращает структуру.
  Отправляет только `Sender`, записывает только `Booker` — и у каждого свои
  проверки, которые нельзя обойти, дописав вызов в стороне. Это проверяется
  тестами на границы импортов.
- **Первыми пишем только то, чего клиент ждёт.** Это напоминание о записи, которую он сам
  подтвердил, — граница из собственного правила Telegram: «only contact people if you're
  sure that they are expecting messages from you». Реактивации и рассылок в коде нет.
  И то, что уходит первым, **не пишет модель** — текст фиксированный.

## Ограничения этапа

| Не входит | Почему |
|---|---|
| Altegio | данные из файлов; на «когда свободно» отвечаем из своего расписания |
| **Возврат и реактивация** | «давно вас не было», продажа абонемента — это маркетинг, из аккаунта не уходит |
| Инструменты модели (tool calling) | два обращения к модели на ответ — дорого при 5 запросах/мин |
| Согласие клиента на ИИ-обработку | тест на себе. Придёт реальный клиент — согласие обязательно |
| Автоподъём процесса после падения | запускается руками. **Напоминания работают только пока процесс жив** |

Напоминания о визите в этап **входят** — см. раздел выше.
