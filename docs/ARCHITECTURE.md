## Карта

```
Telegram (аккаунт салона)
        │  входящее личное сообщение
        ▼
   tg.py ─────────── единственный модуль, знающий про telethon
        │
        ▼
   app.py · Приём      только личные · не свои · дата > старта · группировка
        │
        ▼
   app.py · Контекст   последние N сообщений из Telegram + прайс и окна из файлов
        │
        ▼
   guards.py · заслон  медицинские триггеры, спам ── сработал ──┐
        │                                                        │ модель
        ▼                                                        │ не вызывается
   llm.py · LLMProvider                                          │
        │  → { reply, needs_human, reason, booking }              │
        ▼                                                        │
   ┌──────────────────────────────────────────────┐              │
   │  sender.py · Sender — ЕДИНСТВЕННЫЙ выход     │◄─────────────┘
   │  1 kill switch   2 белый список  3 лимит     │
   │  4 админ ответил раньше   5 needs_human      │
   │  6 текст не пуст                             │◄───── reminders.py
   │  7 сверка цен с прайсом                      │       + цикл в main.py
   │  8 сверка времени с окнами ПО ДНЯМ           │       напоминания за день
   │  9 сверка условий с правилами салона         │       и за 2 часа —
        │                            │                    ЕДИНСТВЕННОЕ, что
        ▼                            ▼                    уходит первым
   ответ клиенту          шаблон «передала администратору»
        │
        ▼
   booker.py · Booker   три заслона → data/bookings.yaml
```

Напоминания входят в `Sender` **сбоку и через ту же дверь**: отдельного выхода в Telegram у
них нет, поэтому они подчиняются тем же `STOP`, белому списку и лимиту. Проверки 7–9 (цены, время, условия) к ним не применяются — им нечего проверять,
текст фиксированный и модель его не писала.

`login.py` — разовый вход в аккаунт (по QR). `main.py` — запуск и **цикл напоминаний**;
сама проводка вынесена в `main.собрать_систему()` — отдельной функцией именно затем,
чтобы её можно было проверить тестом (`tests/test_wiring.py`). Внутри `main()` тест на
неё написать было нельзя: `main()` требует живой Telegram, живой Cerebras и `.env`.

### Напоминания — единственная проактивная отправка

Напоминание уходит клиенту **первым**, поэтому обставлено отдельно:

| Свойство | Как обеспечено |
|---|---|
| Идёт через `Sender` | значит подчиняется `STOP`, белому списку и лимиту |
| Модель к нему не подпускается | текст фиксированный: проверить сообщение, уходящее первым, перед отправкой некому |
| Не уходит дважды | отметка `напомнили` лежит в `bookings.yaml`, а не в памяти процесса |
| Не рассылается после простоя | созревшие после начала визита гасятся молча; из двух созревших уходит только ближайшее |
| Отказ не гасит | `STOP` снят — напоминание уйдёт на следующем тике |
| Бот не обещает того, чего нет | строка про напоминания попадает в промпт только при включённой рассылке |
| **Не умирает молча** | тик обёрнут в `except Exception` с записью в лог: задача создана через `create_task`, её исключение никто не забирает — без перехвата рассылка прекратилась бы навсегда |

Выключается: `REMINDERS=off` в `.env`. В режиме наблюдения выключены всегда.

## Два инварианта, на которых держится безопасность

### 0. Два выхода наружу, и второй слабее — это названо прямо

| Заслон | Ответ модели | Ответ администратора из окна |
|---|---|---|
| Белый список | ✅ | ✅ единственный, который остаётся |
| Файл `STOP` | ✅ | ❌ человек нажал «отправить» осознанно |
| Лимит частоты | ✅ | ❌ человек печатает медленнее лимита |
| Цены / время / условия | ✅ | ❌ это заслоны от выдумки **модели** |

⚠️ §26: выдавать второй выход за такой же, как первый, нельзя. Он существует
потому, что автор текста — человек: администратор вправе дать скидку и назвать
условие, которого нет в правилах, — он их и устанавливает. Прогонять его слова
через заслон от галлюцинаций значило бы блокировать законный ответ ровно в тех
случаях, для которых окно и сделано.

Оба выхода живут в `Sender`, поэтому транспорт по-прежнему вызывается из одного
модуля — за этим следит тест границ.

### 1. Модель не выполняет действий

Она возвращает структуру. Действия выполняют два компонента, и у каждого свои проверки:

| Компонент | Что делает | Заслоны |
|---|---|---|
| `Sender` | отправляет в Telegram | kill switch · белый список · лимит · «админ ответил» · `needs_human` · сверка цен · **сверка времени по дням** · **сверка условий с правилами** |
| `Booker` | пишет запись в файл | время **предложено нами раньше или названо клиентом** · свободно **в момент записи** · нет дубля — **по пересечению интервалов, без мастера** |

### Как это проверяется — четыре уровня

| Чем | Модель | Telegram | Что видит |
|---|---|---|---|
| `pytest` | подменена | подменён | логику и заслоны |
| `tools/mutants.py` | — | — | что у заслона есть зубы |
| `tools/eval_answers.py` | живая | нет | качество одного ответа |
| `tools/simulate.py` | **живая** | подменён | **многоходовые диалоги целиком** |

Имитация нужна не для удобства: все самые дорогие дефекты этапа нашлись только в
многоходовом диалоге с живой моделью — залипание на медицинском сообщении из истории,
подмена услуги при подтверждении, ложные срабатывания заслона времени. Тест с подменённой
моделью такого не находит, потому что наследует представление автора о том, что модель
ответит.

### 2. Границы соблюдаются тестами, а не договорённостью

| Правило | Проверяется |
|---|---|
| `telethon` импортируется только в `tg.py` | `test_telethon_импортируется_только_в_tg` |
| `cerebras` упоминается только в `llm.py` | `test_cerebras_импортируется_только_в_llm` |
| транспорт вызывается только из `sender.py` | `test_отправка_только_через_sender` |
| **вложенные папки тоже проверяются** — до 2026-08-15 нет | `test_нарушитель_во_вложенной_папке_ловится` + мутация `rglob`→`glob` |
| `send_read_acknowledge` не вызывается нигде | `test_read_acknowledge_не_вызывается_нигде` |
| проводка соединена: `STOP`, белый список, история, напоминания | `tests/test_wiring.py` — 9 тестов, 5 мутаций |

Нарушить границу = обойти заслоны, поэтому это тесты, а не стиль.

## Данные и владение файлами

```
data/price.yaml      ваш   · услуги, цены, абонементы, правила
data/schedule.yaml   ваш   · мастера, пол, часы, график, шаг сетки
data/bookings.yaml   кода  · записи
```

**Код никогда не трогает первые два.** Если бы трогал, `yaml.safe_dump` убил бы все
комментарии — а смысл YAML был именно в ручной правке с пояснениями.

**Свободные окна не хранятся, а вычисляются.** Хранимый список мгновенно разошёлся бы с
записями. Формула: смена мастера минус занятые интервалы, шагом сетки, услуга должна
влезать целиком до конца смены.

**Окна разложены по дням, а не склеены.** `guards.Окна` держит `{смещение дня → времена}`
плюс словарь меток («сегодня», «завтра», «14.08» → номер дня) и часы работы отдельно. Метки
собираются там же, где промпт печатает эти слова, — иначе заслон и промпт разойдутся в
вокабуляре. Плоское множество пропускало «сегодня в 20:30», когда 20:30 свободно завтра.

**Запись на диск атомарная:** временный файл рядом + `os.replace`. Если процесс упадёт
посреди записи, останется либо старый файл, либо новый целиком. Вокруг
«прочитал → изменил → записал» стоит `asyncio.Lock`: два чата могут подтвердить
одновременно.

## Окно администратора (этап 2)

```
Telegram ──► Дирижёр ──► Sender ──► ответ клиенту
                            │
                            └─► Решение(администратору) ─► метка «нужен ответ»
                                                             │
   браузер ◄── страница ◄── inbox/api.py ◄────────────────────┘
      │                        ▲
      └── ответ админа ────────┘── Sender.отправить_от_админа ──► клиенту
```

| Маршрут | Что отдаёт |
|---|---|
| `GET /` | страницу. Без токена — данных в ней нет, токен спрашивает уже она |
| `GET /api/channels` | мессенджеры и **сколько в каждом ждут помощи** — первый экран |
| `GET /api/chats?channel=` | ленту выбранного мессенджера: имя, последнее сообщение, 🔵 непрочитанные, 🔴 нужен ответ. Свежие сверху, ждущие над всеми |
| `GET /api/chat/{chat_id}` | переписку **живьём из Telegram** + карточку клиента |
| `POST /api/reply` | ответ администратора через `Sender`; отказ показывается дословно |

Заслон доступа — **отказ по умолчанию**: без верного токена каждый маршрут отдаёт
401 и ни одного байта данных. Токен сравнивается `secrets.compare_digest`, окно без
токена не поднимается вовсе.

⚠️ **Три ограничения ASCII, найденные пробами, а не документацией:**

| Где | Что было | Почему |
|---|---|---|
| путь URL | `/api/тик` ронял запрос | строка запроса кодируется в ASCII |
| **имя параметра** пути | `{чат_id}` → 404 вместо 401 | Starlette ищет имена по `[a-zA-Z_]` и приняла его за буквальный текст |
| **токен** | кириллицу нельзя отправить заголовком | заголовки HTTP кодируются в ASCII/latin-1 |

Последнее закрыто заслоном: `INBOX_TOKEN` не из ASCII отвергается **на старте** с
внятным текстом. Иначе русский токен в `.env` выглядел бы рабочим, а окно молча не
пускало бы.

⚠️ **Границы честно:** HTTPS локально нет, токен идёт открытым текстом по локальной
сети. Это допустимо, пока окно не выходит в интернет; выход = отдельное решение
(туннель или домен + TLS + пересмотр авторизации).

### Три экрана и почему их три

```
мессенджеры            →  лента канала        →  разговор
Telegram  помощь: 2       🔴 Гиорги   16:35      карточка + переписка
Instagram помощь: 1          Нина     14:20      [ поле ввода ]
```

Каналы приходят в окно **списком** (`каналы=[...]`), даже когда их один. Иначе
«добавить Instagram» означало бы переписать все маршруты; мультиканальность —
названная Георгием причина делать окно вообще.

| Свойство | Как обеспечено |
|---|---|
| Видно, где ты нужен, ДО выбора мессенджера | `/api/channels` считает открытые метки по каждому каналу |
| Счётчик про помощь, а не про непрочитанные | считаются метки; непрочитанные остаются даже там, где бот справился сам |
| Лежащий мессенджер не гасит остальные | сбор ленты перехватывает отказ на каждом канале отдельно |
| История берётся у ТОГО канала, откуда чат | иначе окно спрашивало бы переписку Instagram у Telegram |
| **Набранный ответ не стирается** | каркас разговора строится один раз, опрос обновляет только карточку и сообщения; поле ввода не пересоздаётся никогда |

⚠️ Последнее — живой дефект от 2026-08-16: экран разговора перерисовывался целиком
раз в 5 секунд, и текст исчезал у Георгия прямо во время печати. Проверено после
починки в браузере: через два цикла обновления цел и текст, и **позиция курсора**,
и фокус.

## Метка «нужен ответ» — этап 2 начался здесь

`data/handovers.yaml` — единственное, чего Telegram про диалог не знает. Он знает
`unread_count`, но не знает, что бот **передал разговор человеку**: это наше решение.

| Свойство | Как обеспечено |
|---|---|
| Переживает перезапуск | лежит в файле, а не в памяти процесса — тем же приёмом, что отметка `напомнили` |
| Не содержит данных о здоровье | причина хранится **кодом** из закрытого списка (`медицина`, `торг`, `отмена`…). Свободный текст отвергается исключением: иначе туда попало бы сообщение клиента |
| Первый код побеждает | медицинский вопрос, за которым пошёл торг, остаётся медицинским — админ увидит главное, а не последнее |
| Повтор не плодит записей | клиент написал пять раз, пока админ молчит — передача одна |
| Снятие отмечает, а не удаляет | история передач нужна, чтобы считать, как часто бот зовёт человека |
| Битый файл не роняет окно | форма проверяется, мусор отбрасывается. Найдено собственным враждебным тестом: `передачи: не список` ронял чтение через `AttributeError` |

⚠️ **Экземпляр обязан быть один на процесс.** Дирижёр ставит метку, окно её читает —
если создать два объекта `Передачи`, их списки в памяти разойдутся, и запись одного
затрёт запись другого. Поэтому он создаётся в `собрать_систему` и передаётся дальше.

## Две шкалы времени, которые нельзя смешивать

| Что | В каком времени |
|---|---|
| Записи, рабочие часы, свободные окна | **местное время салона** (Тбилиси, UTC+4), строкой `"16:00"` |
| Даты сообщений из Telegram | **UTC**, tz-aware |

Отсечка «сообщение старше запуска» работает с UTC. Расписание — с местным. Наивная дата
не принимается вообще: `guards.Приём` отвергает её отдельной проверкой, иначе сравнение
дало бы `TypeError` в бою.

## Стек

Python 3.14, `telethon`, `cerebras_cloud_sdk`, `PyYAML`, `qrcode`, `pytest`. Один процесс.
Ни Docker, ни БД, ни веб-сервера, ни очереди — для трёх файлов и одного канала это был бы
лишний сервис.

`qrcode` нужен только `login.py`: нарисовать QR в консоли. Чистый Python, Pillow не требуется.
